# Седьмая — структура репозитория

Игра к хакатону на тему 7 ноября: 2D-стратегия выживания о летающей башне над Мглой.

| Путь | Что это |
|---|---|
| `SETUP.md` | Установка и запуск на новом компьютере, работа вдвоём |
| `TZ-sedmaya.md` | ТЗ: механики, формулы ночного расчёта, система событий, формат данных, объём MVP |
| `STORY-sedmaya.md` | Сюжет: мир, персонажи, события по дням, концовки, флаги |
| `data/balance.json` | Числа баланса: старт, двигатель, Мгла, здания, декреты, фракции |
| `data/events.json` | Все события: сюжетные `dNN_*`, отложенные `late_*`, пул `pool_*`, кризисы `crisis_*`. Бытовые советские события пула (кот под товарищеским судом, гранёный стакан, сгущёнка, металлолом, зарядка, самогон, музыка на рёбрах, книга жалоб, приём Ии в пионеры, собака Звёздочка) — `once`, с `minDay` 2–4, чтобы попадать во вторые окна первых дней |
| `data/endings.json` | Концовки (`verdict`: `win`/`lose`), плакаты итога `verdicts`, судьбы персонажей (`fates`; у Звёздочки нет `default` — строка только при флаге), «Характеристика на Председателя» `reference` (группы строк, из каждой первая подходящая по `requires` и `endings`), значки финала `awards`, кристаллы памяти |
| `data/flavor.json` | Тексты для настроения: `radio` — «Радио Седьмой отвечает» в стенгазете, вопрос и ответ на каждый день по порядку |
| `tools/check-data.js` | Проверка данных: `node tools/check-data.js` |
| `src/core/` | Логика игры на чистом TypeScript, без Phaser и DOM: типы данных и состояния (`types.ts`), загрузка `data/*.json` (`data.ts`), стартовое состояние (`state.ts`), условия `requires` (`requires.ts`), генератор с сидом (`rng.ts`), расчёты по башне — жильё, рабочие, Мгла на ярусах, нужный эфир (`tower.ts`), ночной расчёт по ТЗ 4.5 `runNight` и прогноз `forecastNight`/`forecastWarnings` (`night.ts`), очередь утра `buildMorningQueue` (в день 1 — не больше `balance.events.firstDayWindows` окон, только сюжетное) и текст с `extraText` (`events.ts`), доступность, применение и подсказка выбора `choiceAvailability`/`applyChoice`/`previewChoice` (`choice.ts`), концовка и судьбы `resolveEnding`/`characterFates` (`endings.ts`; `state.ending` — путь дня 20 или поражение от ночи), действия дня — стройка, снос, новый и сброшенный ярус, режим двигателя, декреты (`actions.ts`). Всё экспортируется из `index.ts`. Тесты рядом: `*.test.ts` |
| `src/sim/`, `tools/sim.mjs` | Прогон баланса (ТЗ 14). `sim.ts` — `simulate(data, strategy, seed)`: тот же порядок, что `GameLoop` (утро `buildMorningQueue` → `applyChoice` по каждому окну → день: декреты, стройка по прогнозу ночи, новый ярус, режим двигателя → `runNight`), итог — концовка, след по дням, нехватки. Вариант события стратегия выбирает по весам изменений показателей, ресурсов и фракций (`applyChoice` на копии), `prefer` — заранее решённые события, `floors` — штраф ниже порога. Слоты Корня и яруса над ним бот держит под уловители. `strategies.ts` — `merciful` (→ Гавань), `harsh` (→ Свержение), `pragmatic` (→ Крепость), `seeker` (→ Запечатывание), `idle` (ничего не строит → Падение), `random`. `report.ts` — сводка и покрытие событий, вариантов, флагов, концовок. `sim.test.ts` — критерии ТЗ 14: идентичность по сиду, `idle` проигрывает, стратегии расходятся, все концовки достижимы. `tools/sim.mjs` грузит TypeScript через `runnerImport` Vite |
| `src/game/store.ts` | `GameStore`: текущее состояние в браузере; сцены и панели подписываются, меняют только через `dispatch` с функцией из core |
| `src/game/loop.ts` | `GameLoop`: фазы `start → morning → day → night → … → final`. Утро — `buildMorningQueue` и окна событий, день — действия через `act()`, «Завершить день» — `runNight` и анимация ночи, поражение или день 20 — финал. Экран подключается через `LoopView` (в тестах — заглушка без DOM) |
| `src/game/save.ts` | Сохранение в `localStorage` (`sedmaya.save`) после утра и после каждого действия дня; битая запись — новая игра |
| `src/scenes/` | Башня. `tower-model.ts` — чистая модель без Phaser и DOM (перенос `renderTower` из `Tower.dc.html`): `towerInputFromState` (состояние → высота, Мгла, эфир 0..1, показатели, ярусы, шрамы) и `buildTower` (→ группы деталей с ключами, зазор до Мглы, крен, рамка камеры); тесты сверяют её с `renderTower` макета на всех пресетах (детали башни и облака неба). `model.slots` — прямоугольники слотов для кликов. `tower-dom.ts` — кнопки `.tw-hit` поверх слотов (клик → меню стройки) и детали в div с классами `.tw .*` из `sedmaya.css`, обновляет только изменившиеся, анимирует появление и падение ярусов. `TowerScene.ts` — `DOMElement` Phaser, подписи зданий, `setSlotHandler`, `setNight`, твин 500 мс (ночью 1,3 с) между состояниями, небо. Камера на телефоне: башня от звезды до двигателей (`TOWER_FOOT`) как можно крупнее, кадр прижат к звезде, воздух до Мглы — сколько влезет; Мгла въезжает снизу, когда подходит близко, а пока её не видно — `onMistBelow(метры)`. `tower-presets.ts` — наборы из макета: `?preset=day2|good|bad|scars|harbor|abandoned`, в консоли `sedmaya.tower.preset('bad')`, сэмплы последнего перехода — `sedmaya.tower.scene.samples`. В покое (камера на месте, твинов нет) `TowerScene` усыпляет цикл Phaser (`game.loop.sleep`): canvas с небом не перерисовывается каждый кадр. Будят `show()`, изменение окна и изменение отступов интерфейса (опрос раз в 250 мс); при пробуждении часы твинов сдвигаются на время сна, иначе переход перескочил бы к концу. `hold(true)` держит сцену спящей, пока экран закрыт целиком (открытка финала, `sceneAsleep` в `main.ts`). Проверка — `npm run check:sleep` |
| `src/ui/` | Интерфейс обычным HTML/CSS поверх canvas (`#ui`) по макетам: `start.ts` — стартовый экран (с `radio: true` надпись «Всем! Всем! Всем!» ждёт радио: `is-waiting` — тускло, `is-on-air` от звука на каждое слово — вспышка, `is-heard` — ровно; без звука мигает сама по CSS); `radio-splash.ts` — заставка «Включить радио» перед стартовым экраном (план звука Р1): кнопка «Включить радио» — первый жест, звук запускается в нём, тихая ссылка «Играть без звука» (`muted: true`); вид — как `.start`, появление 220 мс, уход 240 мс, при `prefers-reduced-motion` без движения; при выключенном звуке заставки нет; `hud.ts` — шапка по `Main.dc.html` (листок календаря, ресурсы с изменением за ночь из прогноза, плитки с `data-key` для всплывающих чисел; `actions` — кнопки перед меню, сейчас кнопка звука `.snd-hud`, видна в рамке шире 440 px, у́же — звук только в меню и на M); `panel.ts` — правая панель (до 760 px — нижняя с вкладками по `Mobile.dc.html`): шкалы, фракции, декреты, «Надстроить ярус», прогноз на ночь и режим двигателя, красная «Завершить день» (тревога — пульс и причина из `forecastWarnings`). `verdict.ts`, `verdict.css` — плакат итога «Вы выжили!» / «Вы умерли…» перед финалом (`showVerdict` → Promise, касание/клик/Enter/Esc — дальше; фоны без текста `public/verdict/win.webp`, `lose.webp` из макета дизайнера, надпись живым текстом из `endings.json` → `verdicts`, выбор по `verdict` концовки; Правила:
- Комикс вставляется без кода: картинка кадра кладётся в `public/comics/<комикс>/<файл>` (webp/png/jpg,
  лучше портретные, около 1080 px по длинной стороне), в `data/comics.json` у кадра ставится
  `"image": "comics/intro/01.webp"` (без ведущего `/`) вместо `art`; `focus` — какая часть картинки важна
  при обрезке (`"50% 20%"`). Подписи и облачка остаются текстом поверх картинки — рисовать их на ней
  не нужно. `node tools/check-data.js` проверяет, что файлы на месте, тесты — сетки и эпилоги.
- Числа меняются в `data/balance.json`, затем таблицы в ТЗ (раздел 4) приводятся в соответствие.
- Новый флаг описывается в `STORY-sedmaya.md`, раздел 9.
- После правки `data/` запускать `node tools/check-data.js`.

- Правило слоёв: `src/core` не импортирует Phaser, DOM и `src/game|scenes|ui`. Формулы ночи, очередь
  событий и эффекты выборов пишутся в core чистыми функциями `(state, data, …) → state` с тестами;
  сцены и панели только показывают состояние и вызывают `store.dispatch`.
- Все числа — в `data/balance.json`, в коде их нет. Случайность — только через `src/core/rng.ts`
  с состоянием в `GameState.rng`, не `Math.random`.
- Текстовые окна (события, декреты, стенгазета, финал) делаются в `src/ui` на HTML/CSS по макетам
  из `design/project/`. Башня и Мгла — та же разметка `.tw .*`, что в макетах, внутри `DOMElement` Phaser
  (`src/scenes/tower-*.ts`): вид правится в `sedmaya.css` и сразу совпадает в игре и на холсте; Phaser ведёт
  камеру, твины, небо и частицы. Новая деталь башни добавляется в `buildTower` и в `Tower.dc.html` одновременно —
  иначе тест сверки с макетом упадёт.
- Параллельные задачи — каждая в своей ветке и своём worktree, вливаются в `main` часто.
- Макеты опубликованы в https://claude.ai/artifact/Ev5Tb85HnfCwh86g4f8Y3z. После правки файлов в
  `design/project/` их публикуют туда же, корень публикации — `design/`. Сами по себе `.dc.html`
  в браузере не открываются: им нужен `support.js` холста. Для тех, у кого нет Claude Design, те же
  макеты как обычные страницы выкладываются на https://survedern1.github.io/hakaton/design/
  (каталог токенов и анимаций, исходники, `sources.zip`).
- Башня рисуется во внутреннем масштабе `TOWER_K = 12,5` px на метр (ярус 125 px). Артборд, который
  встраивает `Tower`, задаёт `width` в этих пикселях и уменьшает их через `scale`; `hint-size` равен
  итоговому размеру. Режимы компонента: вся башня, `focus="root|tier|spire"` — крупный план яруса,
  `part="building" b="farm" stage="2"` — одно здание. Проверка без браузера: вырезать скрипт из
  `Tower.dc.html` и прогнать `renderTower` в node на всех `TOWER_PRESETS`.
